## 1. Overview

Players can tune how the game runs and feels: a graphics preset, a frame-rate
cap, a resolution scale, an FPS counter, mouse sensitivity, volume and
fullscreen. The options exist mainly to keep the game smooth on weak machines
and in browsers, and the game warns the player when the browser is drawing in
software instead of on the graphics card. Settings belong to the device, not
to a save profile.

## 3. Detailed Design

### 3.1 Options

| Option | Choices | Default | Applies (web) | Applies (Godot, DESIGN CALL) |
|---|---|---|---|---|
| Graphics preset | Low, Medium, High | Medium | After restart | Immediately |
| Frame-rate cap | 30, 60, 120, Off (match monitor) | 60 | Immediately | Immediately |
| Resolution scale | 60%, 75%, 100% | 100% | Immediately | Immediately |
| Show FPS | on / off | off | Immediately | Immediately |
| Mouse sensitivity | 0.0006 – 0.006 (slider, step 0.0001) | 0.0022 | Immediately | Immediately |
| Volume | 0 – 1 (slider, step 0.05) | 0.5 | Immediately | Immediately |
| Fullscreen | button | windowed | Immediately | Immediately |

**DESIGN CALL — apply immediately.** In the Godot port every option applies as
soon as it is changed. An option the engine cannot change at run time says so
next to it and applies at the next start.

The panel opens from the pause menu in a raid and from the hub. The web build
also shows the signed-in account's options there; the Godot port has no
accounts (ADR-0003).

### 3.2 Graphics presets (`QUALITY`)

| Preset | Pixel-ratio cap | Anti-aliasing | Shadows | Shadow map | Grass blades | Draw distance |
|---|---|---|---|---|---|---|
| Low | 1.0 | off | off | 1024 | 2,500 | 110 m |
| Medium | 1.25 | on | on | 1024 | 5,000 | 150 m |
| High | 1.5 | on | on | 2048 (soft) | 9,000 | 200 m |

Shadows use the soft filter only at a 2048 map.

**DESIGN CALL — presets change detail, never play.** In the web build the
draw distance also hides Husks (and containers) that are farther away, so on Low a
small Husk vanishes beyond 66 m and any Husk beyond 110 m while the Heron
reaches 260 m. In the Godot port, presets change only detail (shadows, grass
density, effects, level of detail). Whether a Husk or container is visible
within weapon range is decided by fog and line of sight, the same on every
preset. The web build is left unchanged.

### 3.3 Frame-rate cap

- The cap applies in a raid and while exploring the Sanctuary.
- **Menus, pause and the hub screen always run at 30 fps**, whatever the cap.
- If the monitor already refreshes slower than the cap, the cap is not applied
  (no frames are skipped).
- "Off" draws as fast as the monitor refreshes.

### 3.4 Device check

- The game reads the name of the graphics device it draws with.
- If the name matches a software renderer (SwiftShader, llvmpipe, softpipe,
  "software", "basic render"), the title screen shows a red warning with the
  fix (turn on graphics acceleration in the browser and restart it), and the
  settings panel and FPS counter name the device in red.
- The FPS counter shows frames per second and the device name.

### 3.5 Storage

Settings are saved on the device, separately from save profiles, and every
profile shares them. **DESIGN CALL — per device.** The Godot port keeps them in
one settings file in `user://`, outside `user://profiles/` (ADR-0003). Values
outside the allowed choices fall back to the default.

### 3.6 Known gaps (not built)

Recorded for a later accessibility pass (`/ux-design` accessibility); no rules
exist for them yet:
- Key rebinding.
- Colourblind options (the game relies on colour for rarity, Husk state and
  lift lamps).
- Subtitles or visual cues for audio-only signals (Husk chirps and warnings, the
  lift alarm, the shield breaking).
- Separate volume for music, effects and UI (there is one master volume).
- Gamepad options (ADR-0004 lists gamepad as partial support).

## 4. Formulas

- **Render pixel ratio** = `min(screen device-pixel-ratio, preset pixel-ratio cap) × resolution scale`
- **Aiming sensitivity** = `sensitivity × 0.6 ÷ scope zoom` while aiming down sights
  (zoom is 1 except the Heron's 2.2); hip-fire uses `sensitivity`.
- **Frame cap applied** when `cap ≠ Off` and the smoothed monitor frame time is
  not more than `0.85 × (1000 / cap)` ms; a frame is skipped when less than
  `0.9 × (1000 / cap)` ms have passed since the last drawn frame.
- **Web-build culling (not carried into the port, see §3.2):**
  `Husk shown = distance < draw distance × (small Husk ? 0.6 : 1)`;
  `container shown = |dx| < L and |dz| < L`, `L = min(70, draw distance × 0.45)`.

## 5. Edge Cases

- **Storage blocked** (private browsing): every option silently uses its default.
- **Saved value not in the allowed list** (edited storage): the default is used.
- **Preset changed mid-raid** (web): the note says it applies after the raid.
  In the Godot port it applies at once (§3.1).
- **Monitor below the cap** (e.g. 50 Hz with a 60 cap): no frames dropped.
- **High-DPI screen on Low**: still drawn at pixel ratio 1, then scaled.
- **Software rendering detected**: the game still runs; it only warns.
- **Fullscreen refused** by the browser: `INTENT UNKNOWN`; the button gives no feedback.

## 6. Dependencies

- ADR-0004 (rendering and export): Forward+ on PC, Compatibility on web; presets
  must have a Compatibility look; the 60 fps / 16.6 ms budget.
- ADR-0003 (save profiles): settings live outside the profiles.
- ADR-0002 (game data): preset tables are data, not code.
- `combat.md`: aim-down-sights and the Heron's scope zoom.
- `husk-ai.md`: what the player can see must not depend on the preset (§3.2).
- `sanctuary-hub.md`, `raid-loop.md`: where the panel opens (hub, pause).

## 8. Acceptance Criteria

- [ ] Each option in §3.1 has the listed choices and default, and changing it takes effect without a restart (Godot).
- [ ] Menus, pause and the hub run at 30 fps whatever the cap.
- [ ] A 60 fps cap on a 50 Hz monitor drops no frames.
- [ ] Resolution 60% renders 60% of the pixel ratio the preset allows.
- [ ] Aiming with the Heron gives sensitivity × 0.6 ÷ 2.2.
- [ ] On every preset, a Husk inside weapon range and clear of fog and cover is drawn.
- [ ] A software renderer shows the warning on the title screen and in settings.
- [ ] Settings survive a restart and are the same in every profile.
- [ ] A settings file with an unknown value loads the default for that option.
